SMARTPY 0.25 SYNTAX PRIMER (read carefully; the compiler reports ONE error at a time and the common mistakes below account for nearly all failures):
- All contract code lives inside `@sp.module def main():`. Only constructs that SmartPy's own parser knows are allowed there: it is NOT full Python.
- Every method of a contract class MUST have a decorator: `@sp.entrypoint` (public), `@sp.private(with_storage="read-only")` / `@sp.private(with_storage="read-write")` / `@sp.private(with_storage="read-write", with_operations=True)` (helper callable as `self.helper(x)`), `@sp.onchain_view()`. Never define undecorated helper methods or underscore-prefixed plain methods. A private helper that sends funds or modifies storage needs the matching `with_storage`/`with_operations` argument.
- Storage is `self.data.x`, declared only in `__init__`. Typed empty containers must be cast: `sp.cast(sp.big_map(), sp.big_map[sp.address, sp.nat])`, `sp.cast({}, sp.map[sp.address, sp.nat])`, `sp.cast(set(), sp.set[sp.address])`. `sp.big_map()` / `sp.map()` take no type arguments; there are no `sp.TBigMap` / `sp.TNat` style annotations and no annotated assignments (`x: T = ...`).
- Entrypoint parameters are untyped; pin types with `sp.cast(param, sp.nat)` (or `sp.cast(p, sp.record(a=sp.address, b=sp.nat))`) on the first lines. Several arguments are passed as one record: define a record parameter and read `p.a`, `p.b`, or use a single parameter.
- Numbers: `sp.nat`, `sp.int`, `sp.mutez`. There is no `**` and no `//`; `/` on nats is floor division. Subtracting nats gives an int: use `sp.as_nat(a - b)` (aborts if negative) or `sp.as_nat(a - b, error="MSG")`. Convert with `sp.to_int(n)`. Mutez to nat: `sp.fst(sp.ediv(sp.amount, sp.mutez(1)).unwrap_some())`; nat to mutez: `sp.mul(n, sp.mutez(1))`. No floats, no arbitrary-width ints, no bit shifts beyond what the template shows.
- Maps: `m.get(k, default=0)`, `m[k] = v`, `k in m`, `del m[k]`, iterate with `for x in m.items():` (`x.key`, `x.value`) or `m.keys()` / `m.values()`. Reading a missing key with `m[k]` fails; use `.get(k, default=...)`.
- Require checks: `assert cond, "MESSAGE"`. Sender is `sp.sender`, attached tez is `sp.amount` (mutez), time is `sp.now`, own address is `sp.self_address`. Send tez: `sp.send(address, mutez_amount)`. Time arithmetic: `sp.add_seconds(sp.now, sp.to_int(n))`.
- Calling another contract: `sp.transfer(arg, sp.mutez(0), sp.contract(sp.nat, addr, entry_point="name").unwrap_some())` with the argument type matching the callee. Use a minimal token contract defined in the same module when the Solidity calls an ERC-20.
- No try/catch, no `self.data.x.get(...)` on non-maps, no `require`, no f-strings, no list comprehensions, no `import` inside the module, no recursion.
- The test scenario must live OUTSIDE the module, decorated `@sp.add_test()`, create `main.YourContract(...)`, then `scenario += c`. Entry calls in tests: `c.entry(arg, _sender=account, _amount=sp.mutez(5), _now=sp.timestamp(100), _valid=False)`.
