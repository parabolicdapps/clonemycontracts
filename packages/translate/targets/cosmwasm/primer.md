## CosmWasm 2.2 primer (verified in the build image: Rust 1.81.0, cosmwasm-std =2.2.2, cw-storage-plus =2.0.0, cw20 =2.0.0, cw-utils =2.0.0)

You write ONLY the body of one handler (an execute, a query or the instantiate). Everything else is generated and compiles: Cargo.toml, `msg.rs` (the message enums), `state.rs` (storage and its accessors), `error.rs` (`ContractError`), `events.rs`, `helpers.rs`, the entry points in `contract.rs` (which validates addresses, converts argument types and rejects funds on non-payable messages) and the handler signature. The project has no network access, so only the crates listed here exist.

How the generated code is shaped:
- Execute handler: `pub fn exec_x(deps: DepsMut, env: Env, info: MessageInfo, <args>) -> Result<Response, ContractError>`. Query handler: `pub fn query_x(deps: Deps, env: Env, <args>) -> Result<T, ContractError>`; instantiate has the execute shape. Everything of `cosmwasm_std` is imported (`use cosmwasm_std::*`), plus `ContractError`, `events`, `helpers::*`, `msg::*`, `state::*`.
- Arguments arrive typed as shown in the prompt: addresses are validated `Addr` values; Solidity uint8/16/32 are u8/u16/u32; uint33..64 and mapping keys / array indexes are `u64`; uint65..128 `Uint128`; uint256 `Uint256`; bool, `String`, `Binary` (bytes), `Vec<T>` for arrays.
- `msg.sender` is `info.sender` (an `Addr`; use `&info.sender` or `info.sender.clone()`), `address(this)` is `env.contract.address`, `block.timestamp` is `now(&env)` (a Uint256, seconds), `msg.value` is `sent_value(deps.storage, &info)?`.
- State: every Solidity state variable has accessors (listed in the prompt): `get_x(deps.storage, ..)`, `set_x(deps.storage, .., &v)`. A missing entry reads as the Solidity default (0 / false / zero address), never as an error, so `balances[a] += v` is `let b = get_balances(deps.storage, &a)?; set_balances(deps.storage, &a, &b.checked_add(v)?)?;`. Never use `Item::load`/`Map::load` directly. Structs are read with `get_x`, modified, and written back with `set_x`; dynamic arrays have `len_x`, `push_x`, `pop_x`. Pass `deps.storage` straight in; do not keep a reference across two accessor calls.
- Integers: Uint256/Uint128 have `checked_add/checked_sub/checked_mul/checked_div/checked_pow(u32)` that return `Result` and convert to ContractError with `?` (division by zero and overflow revert like Solidity 0.8); `.is_zero()`, `Uint256::zero()`, `Uint256::from(5u128)`, `Uint256::from(some_u64)`, `Uint256::from(some_uint128)`, comparisons `<` `>=` `==`, `.min(b)`, `.max(b)`, `.saturating_sub(b)`. Do not use `+ - * /` on them (they panic on overflow). Plain u8..u64 use `a.checked_add(b).ok_or_else(ovf)?`. 10**18 is `Uint256::from(1_000_000_000_000_000_000u128)`. To narrow a Uint256 use `to_u128(x)?` / `to_u64(x)?`; to widen a u64 `Uint256::from(x)`.
- Errors: `return Err(ContractError::Variant {});` using the variant whose message equals the Solidity revert message (the prompt lists them). `require(cond, "msg")` is `if !cond { return Err(ContractError::Msg {}); }`. Never use `unwrap`, `expect`, `panic!`.
- Events: `Response::new().add_event(events::name(arg, ..))`; every event argument is `impl ToString` (pass `&info.sender`, `amount`, `true`). `add_attribute("action", "x")` is optional.
- Token calls (the contract talks to a cw20 token): `cw20_transfer(&token, &to, amount)?` and `cw20_transfer_from(&token, &owner, &to, amount)?` return `Vec<CosmosMsg>`: add them with `.add_messages(msgs)`. They are dispatched AFTER the handler returns, so update state first and never read a token balance expecting the transfer to be included. `cw20_balance(deps.querier, &token, &who)?` answers immediately. A failing message reverts the whole transaction, like `require(token.transfer(..))`. `token.transferFrom(msg.sender, address(this), x)` needs the caller's cw20 allowance for this contract; that is by design.
- Native coin (only when the prompt lists the helpers): `bank_send(deps.storage, &to, amount)?` returns `Vec<CosmosMsg>` (`.add_messages`), `contract_native_balance(deps.querier, deps.storage, &env)?` is `address(this).balance`. A low-level `call{value}(data)` only translates the value.
- Return values: an execute handler ends with `Ok(Response::new()...)`. A query handler ends with `Ok(value)`: addresses are returned as `String` (`addr.to_string()`), several return values go in the generated response struct (`Ok(GetTxResponse { to: .., .. })`).
- Modifiers and internal Solidity functions shown in the prompt must be inlined into the body, in the same order as Solidity executes them. A Solidity `require(address != address(0))` is already implied for message arguments (an invalid address is rejected before the handler), keep other zero checks as `is_zero_addr(&x)`.
- Keep every check, the order of checks and effects, the arithmetic semantics and the events. If CosmWasm cannot express something exactly, implement the closest equivalent and add a comment starting with `DEVIATION:`.
- Output the body only, indented by 4 spaces, ending with the `Ok(...)` expression. No placeholders, no TODO, no `unimplemented!`.
